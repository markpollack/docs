## 0.80.0 (unreleased)

<Warning>
**This version has not shipped yet.** This entry describes a release candidate under active
verification; version numbers, dates and content may still change before it's tagged. Don't treat
anything below as available until the [migration guide](/docs/acp-java-sdk/migration-0.80) and this
page say otherwise.
</Warning>

0.80.0 is binary-incompatible with 0.18.0: recompile against it, don't just swap the jar. The full
breaking-change list, with a quick-mapping table from the old API to the new one, is in the
[migration guide](/docs/acp-java-sdk/migration-0.80).

**Spring Boot, Quarkus and Micronaut support, all in the SDK.** All three are required (non-preview)
0.80.0 modules, each the same shape: annotate one `@AcpAgent` class and the framework serves it.

- **Spring Boot**: `acp-spring-boot-starter`/`acp-spring-boot-autoconfigure` move from
  `org.springaicommunity` into `com.agentclientprotocol`, versioned with the rest of the SDK (no
  relocation POM; see the
  [migration guide](/docs/acp-java-sdk/migration-0.80#spring-boot-support-moved-into-the-sdk) for the
  exact coordinate and package change). See [Spring Boot Starter](/docs/acp-java-sdk/autoconfig).
- **Micronaut** (`acp-micronaut`, new): compile-time bean discovery, Micronaut AOP interception works
  on the annotated class, and handlers may return a Reactive Streams `Publisher`. See
  [Micronaut Integration](/docs/acp-java-sdk/micronaut).
- **Quarkus** (`acp-quarkus`, new): build-time (Jandex) discovery, served on Quarkus's own HTTP
  server with no Jetty dependency, and `@Prompt` may return a Mutiny `Uni` or a streaming `Multi`. See
  [Quarkus Integration](/docs/acp-java-sdk/quarkus).

Tutorial modules for Quarkus and Micronaut are coming in a later pass.

**A client's prompt is no longer cut off by the request timeout.** A turn's answer only comes at the
end of it, so the 30-second request timeout used to cancel every prompt that ran longer than that.
`session/prompt` now waits for the turn however long it takes; set the new `.promptTimeout(Duration)`
(`spring.acp.client.prompt-timeout` / `acp.client.prompt-timeout` / `quarkus.acp.client.prompt-timeout`
on the three framework integrations) if you want a bound back. See the
[migration guide](/docs/acp-java-sdk/migration-0.80#a-clients-prompt-is-no-longer-bounded-by-the-request-timeout).

**New concepts and features**, each with its own page:

- **[Session config options](/docs/acp-java-sdk/config-options)** replace `session/set_model`: an
  agent declares its own selectors (model choice is now just the one with `category: "model"`), plus
  a new boolean kind for simple on/off settings.
- **[`$/cancel_request`](/docs/acp-java-sdk/cancellation)**, in both directions, lets either side
  cancel a single in-flight request without ending the whole session. Two new agent-side settings,
  `cancelGracePeriod` (default 60s) and `maxPromptDuration` (off by default), bound how long a prompt
  handler can run; see that page for exactly what they do and why they exist.
- **[Extension methods](/docs/acp-java-sdk/extensions)** (`_`-prefixed custom requests and
  notifications) are now a first-class, typed feature on every client and agent builder, not just a
  raw escape hatch.
- **Elicitation is stable**, with explicit mode-checking: see
  [Elicitation](/docs/acp-java-sdk/elicitation).
- **[Terminal authentication and logout](/docs/acp-java-sdk/terminal-auth-and-logout)**: an agent can
  ask the client to run an interactive login, and advertise that it supports logging out.
- The Streamable HTTP and WebSocket transports gain a graceful shutdown window
  (`shutdownTimeout`) and clearer connection/session routing; see
  [Transports](/docs/acp-java-sdk/transports) for the identity and routing tables.
- **Forward compatibility** got more deliberate: former enums (`StopReason`, `ToolCallStatus`, and
  others) are now open value types, and several unions gained explicit `Unknown*` fallback variants.
  Error codes now match the ACP v1 schema exactly. See
  [Forward compatibility](/docs/acp-java-sdk/forward-compatibility).
- **[One stability convention](/docs/acp-java-sdk/stability)**: an API is unstable if and only if it
  carries `@UnstableAcpApi`. Today that's session fork and the providers methods; everything else,
  including everything listed above, is a stable promise.

**Fixes worth knowing about**

- A handler that throws a bare `Error` now answers `-32603` instead of leaving the caller hanging.
- `AcpAgentSupport.Builder` is safely reusable across multiple `buildFactory()` calls, which the
  Streamable HTTP listener relies on to hand each connection its own agent instance.
- `prompt()` (and every other client request) now returns only after every notification received
  before its response has been handled by the session-update consumer; see
  [Concepts: the ordering guarantee](/docs/acp-java-sdk/concepts#session-updates-and-the-ordering-guarantee).
- Closing a stdio client now lets the agent exit on its own (a 2-second wait) before sending
  SIGTERM, instead of terminating it immediately.

## 0.18.0 (2026-09-25)

Remote agents: the Streamable HTTP and WebSocket transport from the ACP RFD, over plain `http://` and `https://`, and a choice of Jackson 2 or Jackson 3. See [Remote agents](/docs/acp-java-sdk/index#remote-agents-over-streamable-http) for the code.

<Warning>
Three changes need attention when upgrading:

- **`acp-core` no longer contains a JSON implementation.** If you depend on `acp-core` alone, add `acp-json-jackson2` or `acp-json-jackson3`, otherwise `AcpJsonMapper.createDefault()` fails with "No AcpJsonMapperSupplier found on the classpath". `acp-agent-support`, `acp-test`, `acp-websocket-jetty` and `acp-streamable-http-jetty` already bring `acp-json-jackson2`.
- **A second client on an already-connected transport now fails at construction.** A transport instance carries exactly one session.
- **`JacksonAcpJsonMapper` built from a bare `new ObjectMapper()` is now strict about unknown fields.** Start from `JacksonAcpJsonMapper.defaultObjectMapper()` to keep the lenient behavior.
</Warning>

**Added**

- Streamable HTTP transport (RFD [streamable-http-websocket-transport](https://agentclientprotocol.com/rfds/streamable-http-websocket-transport)), contributed by @kamikaz1k (#7). `StreamableHttpAcpClientTransport` in `acp-core` talks to a remote agent over HTTP POST with SSE response streams. The new `acp-streamable-http-jetty` module provides `StreamableHttpAcpAgentTransport`, a Jetty listener that serves HTTP/SSE and a WebSocket upgrade on the same path and hosts one agent per remote connection through `AcpAgentFactory`. Header names and path match the TypeScript and Rust SDKs
- `StreamableHttpAcpServlet` is public and mountable in any Servlet 6 container (Spring Boot, Tomcat, Jetty, Undertow) at your own path; register it with async support. It serves the HTTP/SSE profile; the WebSocket upgrade needs `StreamableHttpAcpAgentTransport`
- Limits and keep-alive for the HTTP agent transport (`StreamableHttpAcpAgentTransportOptions`): POST bodies capped at 16 MiB by default, bounded WebSocket send queues and provisional `session/load` streams, a `: keep-alive` comment every 15 s on attached SSE streams, and 1,024 concurrent HTTP/2 streams per connection instead of Jetty's default 128
- HTTP/2 over plain `http://`: the client sends a bodiless GET first so that, against a server that speaks h2c, every request runs on HTTP/2; otherwise it settles on HTTP/1.1
- The Streamable HTTP client reconnects a dropped SSE stream with a short backoff; it gives up on a 404 or after three reconnects in a row that delivered nothing
- `AcpClientTransport.awaitTermination()`, implemented by the Streamable HTTP and WebSocket client transports: when the transport dies, pending and later requests fail at once with the cause instead of waiting out the request timeout
- JSON modules (#12): the Jackson 2 mapper moved into `acp-json-jackson2`, and `acp-json-jackson3` adds `Jackson3AcpJsonMapper` on Jackson 3 (3.1.5, the version Spring Boot 4.1 manages). Both write the same bytes on the wire. Proposed by @bengbengbalabalabeng
- Deterministic JSON mapper selection by `AcpJsonMapperSupplier.priority()`: with both modules present Jackson 3 wins, and an application's own supplier wins over both. The system property `acp.json.mapper.supplier` names one explicitly
- `CancelNotification` carries `_meta`; `AcpSyncClient(AcpAsyncClient)` is public, so both APIs can share one session

**Changed**

- Breaking: `acp-core` depends on `jackson-annotations` only, not on `jackson-databind` or `jackson-core` (#12). `JacksonAcpJsonMapper` keeps its package and name
- Single-turn enforcement is per logical session (keyed by `sessionId`), because one HTTP connection carries many sessions. Stdio and WebSocket agents behave as before (#7, #9)
- Unknown-field policy moved from the schema records to the mapper (#10). The default mapper stays lenient and logs each ignored property at DEBUG; a strict mapper you pass in is now honored. Reported by @KallivdH
- Request timeouts run on one shared library-owned daemon timer instead of a thread pool per session

**Deprecated**

- `WebSocketAcpAgentTransport` (`acp-websocket-jetty`) is deprecated for removal. It serves a single WebSocket client; `StreamableHttpAcpAgentTransport` serves the WebSocket upgrade for any number of clients, and `WebSocketAcpClientTransport` clients connect to it unchanged

**Fixed**

- A second `AcpClient.async(transport)` or `AcpClient.sync(transport)` on the same stdio transport started a second agent process whose requests could only time out. This was the Spring Boot autoconfiguration failure reported in June 2026. The stdio transport now refuses a second `connect()`, and sessions surface connect failures instead of dropping them
- A second prompt on a session could be rejected with `-32000` or hang under CPU contention (#14): the prompt lock is now released before the response is published. Reported by @krickert
- `WebSocketAcpAgentTransport` wrote frames without waiting for the previous write, and could throw a `NullPointerException` on close
- The agent session reads `sessionId` from typed `PromptRequest` and `CancelNotification` params, so in-process transports match cancels correctly

## 0.17.0 (2026-08-28)

Wire-format correction. No public API change: every constructor and accessor is unchanged, and the ACP surface is identical to 0.16.1.

- Fix the duplicate discriminator on the wire: every polymorphic type wrote its `type` property twice, so `new TextContent("hello")` serialized to `{"type":"text","type":"text","text":"hello"}` and every `session/prompt` carried a duplicate JSON key. Jackson-based peers accept duplicates; a strict parser rejects the message. The type id is now written once and is populated on deserialization (previously `null`). 27 records across 6 hierarchies
