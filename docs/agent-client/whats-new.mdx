## On main (0.32.1-SNAPSHOT, not yet released)

None of this is in 0.32.0. Resolve `0.32.1-SNAPSHOT` from `https://central.sonatype.com/repository/maven-snapshots/` with snapshots enabled, and name the `main` commit you built against: snapshot content changes as `main` moves. Checked against agent-client main `a17b04e9`.

- **Asynchronous lifecycle.** `client.goal(...).runAsync()` returns an `AgentExecution` with `result()`, `result(Duration)`, `awaitTermination(Duration)`, `cancel(boolean)`, `termination()`, `recording()` and `inspect()`. Retained sessions come from `client.sessions().create(...)`, with sequential turns on one `AgentSession`. Providers implement `AgentExecutionProvider`. New modules, not on Central at 0.32.0: `agent-client-claude` (`ClaudeClientProvider`), `agent-client-codex` (`CodexClientProvider`), `agent-client-antigravity` (`AntigravityClientProvider`) and `agent-client-journal` (`JournalExecutionRecorder`). See the [async lifecycle reference](/docs/agent-client/reference/async-lifecycle) and the [async conversation tutorials](/docs/agent-client/tutorial/async/01-one-server-many-conversations)
- **Recording.** `execution.recording()` reports native recording separately from the result, and recording never changes the result. With `agent-client-journal`, `nativeRecording()` reports `ATTACHED`, `UNQUALIFIED`, `REJECTED` or `NOT_CAPTURED`; every outcome archives the call, linked by its decision
- **Failed executions and `fullRecord()`.** A failed `result()` throws `AgentExecutionException`; `failure()` returns a `FailureInfo` (code, exception class, message, causes) that keeps the original failure. Once the capture is sealed, `execution.recording().evidence().fullRecord()` returns a `CaptureRecordReference` (`uri`, `format` = acquisition profile, `sha256`), also when the execution failed. It is diagnostic evidence, not Journal qualification
- **Closing.** Close the client only after the recording has settled: wait while `recording().delivery()` is `Pending`, `Processing` or `Resubmitted`, with a bound. A client with no recording configured reports `NotConfigured`. A client closed earlier seals nothing
- **BUSY refusal.** A submit the session cannot take dispatches nothing and throws `AgentOperationException`, whose `failure()` is `BUSY` (a turn still holds the session), `CLEANUP_UNKNOWN` (the session is quarantined) or `CLOSED`. Before `4de205db` it was a plain `IllegalStateException`; `AgentOperationException` extends `IllegalStateException`, so existing catches still work
- **CLI versions are recorded, not gated.** The Client accepts any Claude Code version on the SDK route and any Codex CLI version on the exec route; the observed version is recorded in the acquisition profile (`claude-code-<version>-sdk-stdio-session-file`, `codex-cli-<version>-exec-stdio-rollout`). With Agent Journal 2.0.0-SNAPSHOT, qualified one-shots are delivered under `client-terminal-claude-sdk/1` and `client-terminal-codex-exec/1`
- **MCP servers.** The ACP route (Grok, Junie) now sends configured MCP servers in `session/new`: stdio always, HTTP and SSE when the agent advertises the transport, otherwise the call fails before a session opens. In 0.32.0 they are dropped. The Claude Code lifecycle provider translates MCP servers and supports a scoped binding (`SessionSpec.binding(new ConnectionBinding(...))`, `refreshBinding(...)`); the Codex and Antigravity lifecycle providers refuse them before launch. See [Give an agent MCP servers](/docs/agent-client/howto/mcp-servers)
- **The ACP route (Grok, Junie) is built on ACP Java SDK 0.81.0.** 0.32.0 used 0.17.0. Client no longer advertises the ACP terminal capability, only file read and write: it never served `terminal/*`, so an agent that asked for a terminal got "method not found", and agents run commands with their own tools. The run timeout now bounds the whole prompt turn, and when it expires the agent receives `$/cancel_request`. A relative working directory is sent to the agent as an absolute path. HTTP and SSE MCP servers are still refused before a session opens unless the agent advertises that transport.
- **Gemini MCP servers no longer touch the workspace.** 0.32.0 and earlier wrote them to `<workspace>/.gemini/settings.json` and deleted it after the run, removing any settings file the workspace already had. On main they go in an owner-only session settings file outside the workspace (`GEMINI_CLI_SYSTEM_SETTINGS_PATH`, allow-listed with `mcp.allowed`). The call is refused when Gemini system settings already exist or the sandbox is not local. See [Give an agent MCP servers](/docs/agent-client/howto/mcp-servers).
- **Breaking: legacy Claude derived tracing removed.** Builder options `traceDir`, `traceContentMode` and `archiveTranscript`; provider fields `phaseCapture`, `tracePath`, `transcriptPath` and the derived token fields; properties `agent-client.claude.trace-dir`, `trace-content-mode` and `archive-transcript`; and `agent-claude`'s Journal 1.x dependency are removed. Use `ClaudeAgentModel.Builder.capture(ClaudeCaptureOptions)` for blocking calls and `ClaudeClientProvider.Builder.acquisitionDirectory(...)` for lifecycle sessions. `AgentClientResponse.getPhaseCapture()` stays; for Claude it returns null. See [legacy tracing removed](https://github.com/markpollack/agent-client/blob/main/docs/legacy-tracing-removed.md)

## 0.32.0 (2026-10-30)

**Fixed**

- The Codex, Gemini, Grok, Junie and Qwen Code starters now provide an `AgentClient.Builder`. `AgentClientAutoConfiguration` runs only when an agent bean exists but declared no ordering, so it could be evaluated before these providers registered their agent; it now runs after every provider auto-configuration
- The Amazon Q starter now declares `agent-client-spring-boot-autoconfigure`, like the other starters, so it provides an `AgentClient.Builder`; this adds `agent-client-core` and `agent-client-spring-boot-autoconfigure` to its dependencies

**Changed**

- One-shot Claude calls merge the request's environment variables over the model's configured defaults, without modifying the defaults
- `codex-cli-sdk` adds `CodexClient.stream(...)`, `CLITransport.stream(...)` and `ExecuteOptions` `environment(Map)` / `configOverrides(Map)`: stream one turn, new or resumed, delivering each JSON line as it arrives
- `DeprecatedPropertyMigrator` implements Spring Boot's `org.springframework.boot.EnvironmentPostProcessor` and its `spring.factories` key changed to match; this matters only to applications that refer to the migrator by type or replace its registration
- The deprecated `AgentModel` interface and the provider models that implement it are unchanged; it will be removed in a later release
- `./mvnw verify` enforces JaCoCo coverage floors, SpotBugs, Error Prone (`-Werror` on main sources), PMD/CPD and ArchUnit package-cycle rules; the gates add nothing to any published module's dependencies

## 0.31.0 (2026-09-17)

- `ClaudeAgentModel.interrupt()` closes the in-flight clients of `call()`, iteration and streaming, so a cancel stops a Claude call that is already running; `close()` delegates to it
- Built on Claude Agent SDK 1.7.0, which destroys the CLI process tree before closing its streams
- `AgentModel` is unchanged; a cancelled `call()` still returns an error response rather than throwing

- Claude traces record the turn ceiling

## 0.29.0 (2026-08-22)

- Grok, Codex, and Antigravity now publish their parsed run trajectory through `AgentClientResponse.getPhaseCapture()`, matching the Claude facade contract; live facade integration gates verify that all three return a capture containing tool uses
- Grok reads its native `streaming-json` ACP stream and Antigravity its `stream-json`; both SDKs retain the full stream for capture while preserving the existing terminal text, status, token, and session fields
- Codex harvests its durable rollout JSONL after execution, locating the matching file by session id or working directory with a bounded wait for delayed flushes
- The three provider adapters consume the released Agent Journal 1.8.0 capture modules; capture stays provider-owned, and `agent-model` and the production surface of `agent-client-core` remain free of journal dependencies
- Repair LOOSE-mode Codex execution: current Codex versions reject `--full-auto` after `exec`, so full-auto now maps to the global `--sandbox workspace-write` and `--ask-for-approval never` options placed before the subcommand
- Keep full-auto distinct from the explicit unrestricted `--dangerously-bypass-approvals-and-sandbox` level, so portable auto-approve no longer grants full-disk access implicitly; add repeated `--add-dir` support for explicitly named writable roots
- Document that provider trajectories come from the `AgentClient` facade response rather than a direct `AgentApi.call()`, and are independent of raw trace-file configuration
- Remove the inert module-local deploy skip from `agent-tck` — the artifact remains published — and delete the orphaned sandbox TCK package, which tested a sandbox SPI this repository no longer owns

## 0.28.0 (2026-08-22)

- Add a Grok CLI provider: `agent-grok`, `grok-cli-sdk`, and `agent-starter-grok`. Headless runs return a real JSON envelope, so session id, token usage and a genuine per-run USD cost are read rather than scraped, and a caller-supplied session UUID makes resume possible without recovering an id from output
- Add an Antigravity CLI provider for Google's `agy`: `agent-antigravity`, `antigravity-cli-sdk`, and `agent-starter-antigravity`
- Drop `--effort` when the Antigravity model slug already encodes it; passing both is a hard error that returns no output, so a portable low-effort request would otherwise produce nothing at all
- Declare the Antigravity working directory with `--add-dir`: setting the process working directory alone lets the CLI divert writes to a shared scratch directory while reporting success
- Derive Antigravity run success from whether work was produced and nothing was refused, rather than from its `status` field, which reports ERROR alongside complete and correct responses
- Detect Antigravity soft denials from both the result envelope and stderr, so a run whose tool calls were refused is not mistaken for one that found nothing to do
- Add `GROK` and `ANTIGRAVITY` to the provider parity TCK and enrol both in the parity scenarios
- Both new providers pass the full provider parity TCK — ten scenarios each, zero skips, zero failures — against live CLIs, joining Claude Code, Codex, and Gemini as the only adapters with parity coverage. CI re-verifies those three on every commit; Grok and Antigravity cannot run there because both CLIs authenticate interactively and cache credentials rather than reading an API key
