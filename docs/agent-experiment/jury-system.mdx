## Why a Jury?

A single judge gives you a single score. A jury gives you *diagnostic information* — when something fails, you know *where* in the stack it failed and *why*.

The experiment driver uses a **cascaded jury** with three tiers. Each tier is more expensive than the last. A `CascadedJury` runs a later tier only when the earlier tier's policy lets it continue; a `SimpleJury` runs every judge.

## The Three Tiers

<Steps>
  <Step title="Tier 1: Deterministic">
    Zero-cost, instant, binary. Checks facts that are unambiguously right or wrong.

    **Examples**: Does the project compile? Does `java -version` report the right version? Are all `javax.*` imports replaced with `jakarta.*`?

    **Cost**: Free (no LLM calls)
  </Step>
  <Step title="Tier 2: Structural">
    Compares the agent's output against the reference implementation at a structural level — AST diffs, import sets, annotation changes, POM dependency trees.

    **Examples**: Are the same imports present? Do method signatures match? Are the right dependencies in the POM?

    **Cost**: Free (structural comparison, no LLM)
  </Step>
  <Step title="Tier 3: Semantic">
    LLM-powered evaluation for questions that can't be answered structurally. Uses criteria extracted from the execution plan to judge whether the agent's approach was sound.

    **Examples**: Is the error handling strategy appropriate? Does the migration preserve business logic semantics?

    **Cost**: LLM tokens per item
  </Step>
</Steps>

## Wiring a Simple Jury

Start with a single Tier 1 judge:

```java
Jury jury = SimpleJury.builder()
    .judge(BuildSuccessJudge.maven("compile"), 1.0)
    .votingStrategy(new MajorityVotingStrategy())
    .build();
```

## Wiring a Multi-Tier Jury

Add judges from each tier with weights:

```java
// Tier 1: deterministic
Judge buildJudge = BuildSuccessJudge.maven("compile");
Judge versionJudge = new ClassVersionJudge();  // expects "targetClassVersion" (65 = Java 21) in the context metadata
// Tier 2: structural (write your own; see "Writing a Custom Judge")
Judge fileJudge = new FileExistsJudge("src/main/java/com/example/Person.java");
// Tier 3: semantic (LLM-powered, through the Claude Code SDK)
Judge semanticJudge = new SemanticDiffJudge(SemanticDiffJudgeConfig.defaults());

Jury jury = SimpleJury.builder()
    .judge(buildJudge, 1.0)
    .judge(versionJudge, 0.8)
    .judge(fileJudge, 0.6)
    .judge(semanticJudge, 0.4)
    .votingStrategy(new MajorityVotingStrategy())
    .build();
```

`FileExistsJudge` is the custom judge from [Getting Started](/docs/agent-experiment/getting-started). This block compiles against 0.9.0.

Weights shape the vote; they do not order execution. To stop before an expensive tier, use `CascadedJury`.

## Stopping early with a cascade

A cascade runs its next tier only when the earlier tier's policy lets it continue. Both blocks compile against their version:

```java
// 0.9.0
Jury jury = CascadedJury.builder()
    .tier("deterministic", SimpleJury.builder()
        .judge(BuildSuccessJudge.maven("compile"))
        .votingStrategy(new MajorityVotingStrategy()).build(), TierPolicy.REJECT_ON_ANY_FAIL)
    .tier("semantic", SimpleJury.builder()
        .judge(new SemanticDiffJudge(SemanticDiffJudgeConfig.defaults()))
        .votingStrategy(new MajorityVotingStrategy()).build(), TierPolicy.FINAL_TIER)
    .build();

// main (0.10.0-SNAPSHOT, not yet released): one cascade per item
Function<AgentJudgingInput, Jury> juries = input -> CascadedJury.builder()
    .tier("deterministic", SimpleJury.builder()
        .judge("build", new BuildSuccessJudge(input::workspace, "./mvnw compile"))
        .votingStrategy(new MajorityVotingStrategy()).build(), RoutingRule.STOP_ON_ANY_OPINION_FAIL)
    .tier("semantic", SimpleJury.builder()
        .judge("semantic", new SemanticDiffJudge(SemanticDiffJudgeConfig.defaults(), plan, input.workspace()))
        .votingStrategy(new MajorityVotingStrategy()).build(), RoutingRule.FINAL_TIER)
    .build();
```

On main, `MajorityVotingStrategy` is in `io.github.markpollack.judge.voting`, `RoutingRule` in `io.github.markpollack.judge.verdict`, and `TierPolicy` is gone; `plan` is the item's plan text.

## Writing a Custom Judge

Implement `JudgeWithMetadata`, a `Judge` that also describes itself. This compiles against 0.9.0; it is named `MavenCompileJudge` so it does not shadow Agent Judge's own `BuildSuccessJudge`:

```java
public class MavenCompileJudge implements JudgeWithMetadata {

    @Override
    public Judgment judge(JudgmentContext context) {
        try {
            Process p = new ProcessBuilder("./mvnw", "compile").directory(context.workspace().toFile()).start();
            int exitCode = p.waitFor();
            return exitCode == 0
                ? Judgment.pass("Build succeeded")
                : Judgment.fail("Build failed with exit code " + exitCode);
        }
        catch (IOException e) {
            return Judgment.error("Could not run the build: " + e.getMessage());
        }
        catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return Judgment.error("Interrupted while building");
        }
    }

    @Override
    public JudgeMetadata metadata() {
        return new JudgeMetadata("maven_compile",
            "Verifies the project compiles after agent modifications", JudgeType.DETERMINISTIC);
    }
}
```

### Judge interface

| Method | Returns | Description |
|--------|---------|-------------|
| `judge(JudgmentContext)` | `Judgment` | Evaluate the agent's output |

### JudgmentContext provides

| Field | Type | Description |
|-------|------|-------------|
| `workspace()` | `Path` | Agent's modified workspace |
| `goal()` | `String` | The task the agent was given |
| `agentOutput()` | `Optional<String>` | The agent's output, when it produced one |
| `status()` | `ExecutionStatus` | How the agent's execution ended |
| `metadata()` | `Map<String, Object>` | Item metadata |

Agent Judge 0.17.0's `JudgmentContext` is `(goal, workspace, executionTime, startedAt, agentOutput, status, error, metadata)`. It has no reference-path accessor.

### Judgment fields

| Field | Type | Description |
|-------|------|-------------|
| `status` | `JudgmentStatus` | Required outcome: `PASS`, `FAIL`, `ABSTAIN`, `NOT_APPLICABLE`, or `ERROR` |
| `score` | `Double` (optional) | Explicit normalized score in `[0.0, 1.0]`; use `effectiveScore()` for a numeric view of PASS/FAIL |
| `label` | `String` (optional) | Independent classification label when the judge assigned one |
| `reasoning` | `String` | Human-readable explanation |

Agent Judge 0.17.0 keeps outcome, normalized score, and label as independent facts. A Boolean outcome
uses `Judgment.pass(...)` or `Judgment.fail(...)`; it does not duplicate the same fact in a score
object. `ABSTAIN`, `NOT_APPLICABLE`, and `ERROR` contribute no effective score.
On main, Agent Judge 0.19 removes `JudgmentContext`; see the main-only note.

<Note>
On main (0.10.0-SNAPSHOT, not yet released) a jury is built per item from `AgentJudgingInput`, judges implement `Judgment judge()`, `Judgment` lives in `judge.judgment`, and voting strategies in `judge.voting`. See the main tab of [Getting Started](/docs/agent-experiment/getting-started). None of this is in 0.9.0.
</Note>
