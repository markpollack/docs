## Build the source artifacts

You need Java 21 and the committed Maven wrapper. Use your existing Agent Judge checkout
and the standard `~/.m2/repository`; no second producer clone or repository setting is needed.
The reproducible source revision is `904c1983c3c919b873ca03beb7e321759580ee14`.
Fetch current main and preserve any local changes before updating it. The check below refuses
another revision; it does not reset or move your checkout.

From the Agent Judge checkout:

```bash
export EVAL_M2="$HOME/.m2/repository"
test "$(git rev-parse HEAD)" = "904c1983c3c919b873ca03beb7e321759580ee14"
./mvnw -B -ntp clean install
```

This installs the complete reactor, including the parent and every module, with tests enabled.
It replaces artifacts at the same snapshot coordinates and preserves unrelated versions.
Keep the selected repository when building callers; a producer build alone does not prepare
caller dependencies and Maven plugins. The [requirements example](/docs/agent-judge/requirements-judges#run-a-prepared-example)
has a complete caller POM and executable Java example with deterministic responses.

For an optional isolated installation, set `EVAL_M2` to an absolute task-owned directory and run
`./mvnw -B -ntp -Dmaven.repo.local="$EVAL_M2" clean install` from a clean checkout at the same revision.
Use that repository for subsequent caller and child builds. These commands install locally;
they do not publish artifacts. Prepare dependencies online before using Maven's `-o` option.

For the [PetClinic walkthrough](/docs/agent-judge/petclinic-case-study), open the ordinary tutorial
checkout beside Agent Judge and run `./scripts/prepare-petclinic-demo.sh`. It prepares source
artifacts, callers, plugins and the materialized subject together. Its configured run guide and
presenter runbook cover IntelliJ, offline replay and the optional `--isolated` mode.
No live inference is required.

## Configure, execute, retain

1. Define or read the actual Requirement and its immutable source/revision.
2. Select prepared evidence, an acquisition supplier, or a native investigative runtime configured with workspace/tools.
3. Construct a ready Judge or Jury using typed builders.
4. Execute `judge()` or `vote()`, or one cached AssertJ stage.
5. Keep the whole result and optionally request an application reliance policy.
6. Store/reopen V6 results with the explicit Jackson support module.

## Dependencies

All source artifacts retain group `io.github.markpollack` and version `0.18.0-SNAPSHOT`.
Declare the source version explicitly; no AgentWorks BOM change is implied.
The inventory is 14 JAR modules plus `agent-judge-parent` (POM packaging).
The [0.18 migration guide](/docs/agent-judge/migration-0.18) explains the intentional API and wire breaks.

| Artifact | Purpose |
|---|---|
| `agent-judge-core` | Pure requirements, Judge/Jury construction, results, voting, policy |
| `agent-judge-ai-core` | EvalModel, native RFC2119/EARS requirements and producers |
| `agent-judge-json-jackson2` | Explicit Jackson 2 converters and strict V6 codecs |
| `agent-judge-assertj` / `agent-judge-assertions` | Fluent assertions / retained assertion checks |
| `agent-judge-llm` / `agent-judge-agent-client` | Generated runtime adapters |
| `agent-judge-jev` | Typed structured native execution |
| `agent-judge-exec` / `agent-judge-file` | Build/command and file evaluation |
| `agent-judge-rag` | Typed retrieval evidence and RAG judges |
| `agent-judge-spring-ai` / `agent-judge-langchain4j` / `agent-judge-koog` | Evaluated response evidence bridges |

The [fundamentals path](/docs/agent-judge/tutorial) still demonstrates released 0.17.0 in its separate reactor.
The [PetClinic source path](/docs/agent-judge/petclinic-case-study) demonstrates configured 0.18 APIs.
For historical consumer changes, keep the [0.17 migration guide](/docs/agent-judge/migration-0.17) at its original semantics.
