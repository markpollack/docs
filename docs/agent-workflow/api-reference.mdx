This reference covers **0.13.0**, the prepared executable-DSL milestone.
The [tutorial](/docs/agent-workflow/tutorial) includes complete compiling examples.

## Definition

| Entry point | Meaning |
| --- | --- |
| `Workflows.define(name)` | Begin an authored definition; stable labels contribute to workflow identity. |
| `then(step)` / `then(label, step)` | Append a concrete typed Step instance. |
| `subWorkflow(label, validated)` | Invoke an isolated reusable child within the same durable run. |
| `decision(label, step)` | Route on a concrete enum result; cover every constant exactly once with `when`. |
| `verdict(label, assessment)` | Route a usable native Verdict over all four conclusions. |
| `parallel(label).allSuccessful()` | Declare named static branches and successful full settlement. |
| `forEach(label).maxItems(n).maxInFlight(m).allSuccessful()` | Author one body for each accepted runtime input occurrence. |
| `end()` | Close the innermost choice, parallel group or item body and return to its enclosing stage. |
| `terminate(SUCCEEDED)` | End a successful execution path. |
| `terminate(FAILED/CANCELLED, reason)` | End with an explicit local non-success reason; propagation prevents a successful parent result. |
| `build()` | Freeze and validate a terminal stage, or a completed root choice with semantically closed paths. |
| `maxDuration(duration)` | Bound a workflow/child with a finite positive local duration. |

Parallel branches and fan-out bodies return values to their enclosing join; they do not author independent success terminals.
Choices inside them still support explicitly non-success paths.
Empty continuing choice arms retain incoming data.
Incomplete arms, unreachable work and ambiguous bindings refuse compilation.

## Typed data

`Step<I,O>` declares input and output through a concrete class signature.
Raw implementations and erased lambdas cannot provide these contracts.
An unambiguous compatible whole value binds directly; otherwise a record input can combine legally visible values one level deep.
The first Step's declared input is the submitted root value, including a whole input record.
Type arguments such as `List<FileReview>` remain part of the contract.
Record component names do not select Step names.
See [Parameterization](/docs/agent-workflow/parameterization).

## Registration and runtime

`StepRegistry` holds application-supplied objects.
`ExecutionCompatibility` declares build/settings identity and observes codec/JDK compatibility; it does not archive implementation code.
`ExecutionPolicy` separately bounds physical Step concurrency, attempts, depth and logical invocation count.
`DurableWorkflows.open(...)` owns a local JDBC store.
`start(...)` durably admits an idempotent submission; `resume(...)` drives or recovers the saved run.
`result(...)` exposes its successful final value.
The application supplies compatible definitions and dependencies after recovery.
See [Durability](/docs/agent-workflow/durability).

## Consolidation addition: subsequent release only

The consolidation branch adds `build()` to `Workflows.Sequence` for a final child that always fails or cancels.
This method is **not available on that stage in 0.13.0**.
It adds no implicit terminal and does not permit dangling ordinary paths or unreachable successors.
No new version is selected.
