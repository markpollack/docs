This tutorial uses the **0.13.0 executable DSL** and deterministic Java Steps.
It makes no provider calls and needs no API key.
0.13.0 is prepared for publication; use its staged artifacts until Maven Central publication is confirmed.
Durable loops, waits/timers and committed-event Journal projection are unavailable in this milestone.

## Define business contracts

Use concrete classes implementing `Step<I,O>`.
Pass services and settings through their constructors.
Return business values from `execute`; use `StepContext` only for execution metadata.

```java
public record Request(String repository, int number) {}
public record Diff(String revision, String text) {}
public record ReportInput(Request request, Diff diff) {}
public record Report(String text) {}

var fetch = new Fetch("revision-17");
var report = new WriteReport();
var workflow = Workflows.define("sequential-review")
    .then(fetch).then(report).terminate(SUCCEEDED).build();
```

`Fetch` declares `Step<Request, Diff>` and `WriteReport` declares `Step<ReportInput, Report>`.
The next Step's input record states which typed earlier values it needs.
The complete implementations and runtime wiring are in [Sequential.java](https://github.com/markpollack/workflow-dsl-examples/blob/tutorial/workflow-dsl-consolidation-20261008/executable-dsl/src/main/java/example/Sequential.java) and [ExampleRunner.java](https://github.com/markpollack/workflow-dsl-examples/blob/tutorial/workflow-dsl-consolidation-20261008/executable-dsl/src/main/java/example/ExampleRunner.java).

## Dependencies and execution

Use Java 21 and `io.github.markpollack:workflow-batch:0.13.0`.
Native Verdict routing also needs `io.github.markpollack:agent-judge-json-jackson2:0.18.0`.
Judge 0.18.0 is published; Workflow 0.13.0 remains a prepared candidate.
Until publication is confirmed, use staged Workflow artifacts.

Follow the [six-lesson tutorial](/docs/agent-workflow/tutorial) to compile and execute the example.
Separate definition, Step registration and runtime configuration as shown there.
No Spring container or provider is needed.

## Supported composition

Sequences, reusable nested workflows, exhaustive enum decisions, native Verdict routing, static parallel groups and bounded runtime fan-out compose through the same compiler and durable runtime.
`end()` closes the innermost lexical block; explicit terminals declare execution completion.
Durable loops and timers are deferred.
There is no supported durable Temporal or interchangeable-runner contract for this milestone.
See [Durability](/docs/agent-workflow/durability) before using a saved store.
