## On main (1.8.0-SNAPSHOT, not yet released)

<Warning>
**Published 1.7.0 ships vulnerable Jackson.** It declares Jackson 2.22.2 and 3.2.2 at compile scope, which carry CVE-2026-89407, CVE-2026-89425, CVE-2026-91776 and CVE-2026-91777 (CVSS 7.5); 1.5.1 and 1.6.0 declare the same versions. The fix is on main only. Until 1.8.0 is released, manage Jackson at 2.22.3 / 3.2.3 or later yourself, or use `1.8.0-SNAPSHOT`; see [Using development snapshots from main](/docs/development-snapshots).
</Warning>

Checked against `markpollack/claude-agent-sdk-java@2f31aff8`. None of this is in 1.7.0.

- **Jackson 2.22.2 → 2.22.3 and 3.2.2 → 3.2.3** for the four CVEs above (`bc89a1da`); the standalone-consumer gate's floors are raised to match
- **Verbatim lines.** `CLIOptions.Builder.rawLineListener(Consumer<String>)` receives each standard-output line exactly as read, before the SDK trims, skips or parses it; `ParsedMessage.rawJson()` returns the original JSON line for every message kind (`762a4854`, `79df7a4a`). Source change: code that calls `new CLIOptions(...)` directly passes the new component
- **MCP: fail before launch.** A requested `--mcp-config` that cannot be written fails before the CLI is launched, with `TransportException("Failed to prepare required MCP configuration")`. In 1.7.0 the SDK logged a warning and launched without the MCP servers (`f555e72b`)
- An optional transport observer exposes the original process bytes (`a706fc72`); observed process cessation is bounded and transport resource receipts are exposed (`a9a318bd`, `bd033eba`)
- Native hook output fields are preserved in both client responses (`2f31aff8`), and each control-response subtype is serialized once (`f1d68751`)

## 1.7.0 (2026-09-17)

- **Close no longer hangs.** Transport `close()` and `closeGracefully()` destroy the Claude CLI process tree before closing its streams, so a blocked reader gets EOF: one measured close went from 3 minutes 20 seconds to 34 ms, and a cancelled CLI no longer survives into the next turn
- No API change and no dependency change since 1.6.0. Agent Client 0.31.0 builds on this release for run cancellation
- Ships Jackson 2.22.2 / 3.2.2; see the warning above

## 1.5.0 (2026-08-19)

A security, packaging and behaviour-correction release. No public API changed; every
1.4.0 program compiles against 1.5.0 unmodified.

**Consumer dependency floors.** If you depend on `claude-code-sdk` without importing a
BOM, 1.4.0 resolves Jackson 2.21.2 and Jackson 3.0.3 — 23 known vulnerabilities, 8 of
them HIGH. The project's own build was clean, which is why this went unnoticed: POM
flattening strips `<dependencyManagement>`, so the parent's Jackson BOM imports never
travelled to consumers. 1.5.0 declares the floors — Jackson 2.21.6 and Jackson 3.1.6 —
directly on the published module, and the same no-BOM consumer resolves zero findings.
Upgrading is the fix; nothing makes 1.4.0 safe retroactively.

**`connect()` no longer sends a synthetic `"Hello"`.** Both the sync and the async client
used to substitute the literal string `"Hello"` when `connect()` was called with no
initial prompt, and send it as a user message — contradicting the documented contract
("connects to the Claude CLI without an initial prompt") and billing a model turn the
caller never requested. `connect()` now starts and initialises the session and writes
nothing to the CLI, matching the official Python SDK. `connect(String)` is unchanged and
still sends exactly the prompt you pass; if you relied on the old behaviour, call
`connect("Hello")` explicitly.

**Packaging.** The binary, sources and Javadoc archives now embed the Apache 2.0 licence
text. A CycloneDX 1.6 SBOM is published for the first time. The published POM resolves
from Maven Central only.

**Hygiene.** A hard-coded developer path shipped in `ClaudeCliDiscovery` since the first
release; it is gone. Prompt text and the full CLI command line are no longer written to
INFO logs.
