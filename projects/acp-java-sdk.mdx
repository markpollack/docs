**Current release: 0.81.0** · [What's New](/docs/acp-java-sdk/whats-new) · [Maven Central](https://central.sonatype.com/artifact/com.agentclientprotocol/acp-core) · [GitHub](https://github.com/agentclientprotocol/java-sdk)

A pure Java implementation of the [Agent Client Protocol](https://agentclientprotocol.com/) (ACP), the
standard that lets editors such as Zed, JetBrains IDEs and VS Code talk to coding agents. Build agents
that any ACP client can connect to, or build clients that drive any ACP agent. Java 17+.

## An agent is one annotated class

```java
import com.agentclientprotocol.sdk.annotation.AcpAgent;
import com.agentclientprotocol.sdk.annotation.Prompt;
import com.agentclientprotocol.sdk.spec.AcpSchema.PromptRequest;

@AcpAgent(name = "echo-agent", version = "1.0.0")
public class EchoAgent {

    @Prompt
    public String prompt(PromptRequest request) {
        return "Echo: " + request.text();
    }
}
```

That is a complete ACP agent. Everything else is derived from the class:

- **`initialize` is answered for you.** `agentInfo` comes from `@AcpAgent`, and each handler method
  advertises the capability it implements. There is no `@Initialize` method to write.
- **`session/new` is answered for you** with a generated session id, until you add a `@NewSession`
  method of your own.
- **A `String` return is the reply.** It is streamed to the client as an agent message, and the turn
  ends. Return a `PromptResponse`, a `Mono` or a `CompletionStage` when you need more control.

Add a method, gain a capability: `@LoadSession`, `@ListSessions`, `@ResumeSession`, `@CloseSession`
and `@Logout` each advertise theirs automatically, and `@Prompt(image = true)` declares the prompt
content you accept. Everything else in the protocol is one annotation away too: `@Cancel`,
`@Authenticate`, `@SetSessionConfigOption`, and `@ExtRequest` for methods of your own. Take a
`SyncPromptContext` parameter to stream progress, ask the client for permission, or check for
cancellation. Mistakes, such as two `@Prompt` methods or a parameter nothing can supply, fail when the
agent is built, naming the class, the method and the fix. See
[Clients and Agents](/docs/acp-java-sdk/clients-and-agents) for the full model.

### The lower-level APIs are still there

When you want to wire every handler yourself, write the same agent with the sync or async builder. All
three styles speak the same protocol.

<Tabs>
  <Tab title="Sync builder">
    ```java
    AcpSyncAgent agent = AcpAgent.sync(new StdioAcpAgentTransport())
        .initializeHandler(req -> InitializeResponse.ok())
        .newSessionHandler(req -> new NewSessionResponse(UUID.randomUUID().toString()))
        .promptHandler((req, context) -> {
            context.sendMessage("Echo: " + req.text());
            return PromptResponse.endTurn();
        })
        .build();

    agent.run();
    ```
  </Tab>
  <Tab title="Async builder (Reactor)">
    ```java
    AcpAsyncAgent agent = AcpAgent.async(new StdioAcpAgentTransport())
        .initializeHandler(req -> Mono.just(InitializeResponse.ok()))
        .newSessionHandler(req -> Mono.just(new NewSessionResponse(UUID.randomUUID().toString())))
        .promptHandler((req, context) -> context.sendMessage("Echo: " + req.text())
            .then(Mono.just(PromptResponse.endTurn())))
        .build();

    agent.start().then(agent.awaitTermination()).block();
    ```
  </Tab>
</Tabs>

## One agent, every Java framework

**The same `EchoAgent` runs on Spring Boot, Micronaut and Quarkus, and in plain Java with no framework
at all.** The handler class doesn't change. Only the startup differs: how the framework learns that the
class is a bean, and how the application starts. On Quarkus the class is used exactly as written.

<Tabs>
  <Tab title="Plain Java">
    No framework and no container: one dependency and a three-line `main`.

    ```xml
    <dependency>
        <groupId>com.agentclientprotocol</groupId>
        <artifactId>acp-agent-support</artifactId>
        <version>0.81.0</version>
    </dependency>
    ```

    ```java
    public static void main(String[] args) {
        AcpAgentSupport.create(new EchoAgent())
            .transport(new StdioAcpAgentTransport())
            .run();
    }
    ```

    [Clients and Agents →](/docs/acp-java-sdk/clients-and-agents)
  </Tab>
  <Tab title="Spring Boot">
    Spring Boot 4.1. Make the agent a bean with `@Component`, and the starter finds it and serves it.

    ```xml
    <dependency>
        <groupId>com.agentclientprotocol</groupId>
        <artifactId>acp-spring-boot-starter</artifactId>
        <version>0.81.0</version>
    </dependency>
    ```

    ```java
    @Component
    @AcpAgent(name = "echo-agent", version = "1.0.0")
    public class EchoAgent { /* unchanged */ }

    @SpringBootApplication
    public class Application {
        public static void main(String[] args) {
            SpringApplication.run(Application.class, args);
        }
    }
    ```

    Over stdio, standard output carries the protocol, so keep everything else off it:

    ```properties
    spring.main.keep-alive=true
    spring.main.banner-mode=off
    logging.console.enabled=false
    ```

    [Spring Boot Starter →](/docs/acp-java-sdk/autoconfig)
  </Tab>
  <Tab title="Micronaut">
    Micronaut 4. Make the agent a bean with `@Singleton`. It is discovered at compile time, with no
    classpath scan.

    ```xml
    <dependency>
        <groupId>com.agentclientprotocol</groupId>
        <artifactId>acp-micronaut</artifactId>
        <version>0.81.0</version>
    </dependency>
    ```

    With `micronaut-inject-java` on the annotation processor path, as in any Micronaut application:

    ```java
    @Singleton
    @AcpAgent(name = "echo-agent", version = "1.0.0")
    public class EchoAgent { /* unchanged */ }

    public class Application {
        public static void main(String[] args) {
            Micronaut.build(args).mainClass(Application.class).banner(false).start();
        }
    }
    ```

    Over stdio, send logging to standard error (in `logback.xml`), since standard output carries the
    protocol.

    [Micronaut →](/docs/acp-java-sdk/micronaut)
  </Tab>
  <Tab title="Quarkus">
    Quarkus 3.40, JVM mode. `@AcpAgent` is itself a bean-defining annotation, so the class needs no
    other annotation, and there is no `main` method to write.

    ```xml
    <dependency>
        <groupId>com.agentclientprotocol</groupId>
        <artifactId>acp-quarkus</artifactId>
        <version>0.81.0</version>
    </dependency>
    ```

    ```java
    @AcpAgent(name = "echo-agent", version = "1.0.0")
    public class EchoAgent { /* unchanged */ }
    ```

    Build it with `quarkus-maven-plugin` like any Quarkus application, and run
    `target/quarkus-app/quarkus-run.jar`. Over stdio, the extension sends logging to standard error
    for you.

    [Quarkus →](/docs/acp-java-sdk/quarkus)
  </Tab>
</Tabs>

Each of these starts as a stdio agent, the way an editor launches one. To serve the same agent to
remote clients over Streamable HTTP and WebSocket, set one property:
`spring.acp.agent.transport.type=http`, `acp.agent.transport.type=http` or
`quarkus.acp.agent.transport.type=http`. Spring Boot and Micronaut also need the HTTP module their page
names. In a Spring Boot web application, and in Quarkus, the agent is mounted on the application's own
server, behind its own security. See [Transports](/docs/acp-java-sdk/transports#deployment-topologies)
for every deployment shape, plain Java included.

<Note>
This is tested, not just documented. Every release is gated on a framework smoke matrix: one shared
handler class, hosted by Spring Boot (servlet and WebFlux), Micronaut and Quarkus, is driven by the
TypeScript SDK over stdio, Streamable HTTP and WebSocket. See
[Cross-SDK Compatibility](/docs/acp-java-sdk/compatibility).
</Note>
