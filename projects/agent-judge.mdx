**Version 1.0.0** (2026-11-15) · on Maven Central · **[What's New →](/docs/agent-judge/whats-new)**

**The agent says it is done. Should you merge?** Agent Eval answers with evidence, not a vibe. Write the requirements
before the work, configure a `Judge` or a `Jury` with them, the evidence and the runtime, then call `judge()` or `vote()`.
You get back every original answer, which requirement it was about and what each model or tool call did, and you decide
separately whether your application may rely on it. Compilers, tests and analyzers stay in charge of what they can settle;
a model is asked only where a written requirement needs interpretation.

Formerly Agent Judge. The Maven coordinates (`io.github.markpollack:agent-judge-*`) and Java packages are unchanged.

```xml
<dependency>
  <groupId>io.github.markpollack</groupId>
  <artifactId>agent-judge-core</artifactId>
  <version>1.0.0</version>
</dependency>
```

Java 21. Add `agent-judge-ai-core` for EARS and RFC 2119 requirements, `agent-judge-json-jackson2` for stored results and
`agent-judge-assertj` for test assertions, all at `1.0.0`; [Getting started](/docs/agent-judge/getting-started) lists all
14 modules.

```java
var integrity = Rfc2119Requirement.of("integrity", "1", "MUST",
    "preserve all original judgments", "auditability", null);
// judgeModel is an EvalModel configured by the application.
var nativeRecipe = Rfc2119Judge.builder().runtime(judgeModel);
assertThat(integrity).judgedBy(nativeRecipe)
    .withEvidence("Recorded execution evidence").isSatisfied();
```

## 1.0.0 in brief

Agent Judge is now Agent Eval, and it moves from 0.18.0 to 1.0.0; there is no 0.19.0. Requirement documents are read
whole, strictly and as CommonMark, with a specification linter. Generated audits refuse an oversized prompt before calling.
Generated-answer invocations store message digests instead of messages (`generated-answer:v3`). Three API changes need
attention when you upgrade from 0.18.0: `EvalModel` is no longer an `EvalRuntime`, `BuildSuccessJudge` is no longer a
`CommandJudge`, and code compiled against 0.18.0 must be recompiled. The [What's New](/docs/agent-judge/whats-new) page
lists each one. Versions do not follow semantic versioning: a deliberate breaking change moves the major version.

The [tutorial](/docs/agent-judge/tutorial), with its eleven fundamentals modules and the PetClinic case study, uses released 1.0.0.

## Requirements, evidence and execution

Keep using javac, JUnit and static analysis for questions they can settle. Use a model or agent
when checking a written requirement needs interpretation. Prepared evidence is supplied explicitly;
workspace, tools and timeout are configured on an investigative backend.

`EarsJudge` and `Rfc2119Judge` assess one actual requirement. `EarsJury` and `Rfc2119Jury` assess a
selected roster. A generated investigative roster enters its backend once for the whole roster;
that backend can make several internal model and tool calls. A structured runtime executes once
per requirement and retains those individual invocation owners.

[The PetClinic case study](/docs/agent-judge/petclinic-case-study) uses the same unchanged subject:

| Question | Retained answers | Verdict conclusion |
|---|---|---|
| Does the candidate build and pass its existing tests? | Real deterministic build | PASS Judgment |
| Do the selected six EARS requirements hold? | 6 PASS | PASS |
| Do all 52 EARS requirements hold? | 51 PASS; UC6-AC41 ABSTAIN | INCONCLUSIVE |
| Do all 13 architectural requirements hold? | 5 PASS; 8 FAIL | FAIL |

The model-backed rows replay archived responses. Fresh replay verifies the configured public
caller and retention, rather than establishing new model findings about the subject.

## Keep the result and the reliance decision

A `Judgment` keeps PASS, FAIL, ABSTAIN, NOT_APPLICABLE and ERROR distinct. A `Verdict` additionally
retains the roster, actual requirement associations, child attempts and original results.
Native facts and invocation ownership stay attached; absent recorded usage remains unknown.
A refused native result preserves its complete original, including its own Checks and invocations.

Application policy is a separate decision. Withholding reliance on a PASS Verdict does not rewrite
its conclusion. Producer AssertJ stages evaluate once, cache the complete result or failure,
and can apply policy once. V6 storage retains the corresponding EvaluationResult. Retained reads
and assertions execute no producers or policies.
