**Version 1.8.0** (2026-11-15) · on Maven Central · **[What's New →](/docs/claude-agent-sdk/whats-new)**

**Claude Code, programmable from plain Java.** The SDK runs the Claude Code CLI as a child process and gives you three
ways to talk to it over the same transport: `Query` for a one-shot answer, `ClaudeSyncClient` for blocking multi-turn
sessions and `ClaudeAsyncClient` for reactive streams with Project Reactor. Hooks, permission callbacks, MCP servers,
subagents and structured output come with it. Pure Java, with no native code and no Spring dependency: the SDK needs only
zt-exec, Jackson, Reactor, SLF4J and the MCP Java SDK. Spring Boot auto-configuration for Claude lives in
[Agent Client](/projects/agent-client), whose Claude provider, `agent-claude`, is built on this SDK.

```xml
<dependency>
    <groupId>io.github.markpollack</groupId>
    <artifactId>claude-code-sdk</artifactId>
    <version>1.8.0</version>
</dependency>
```

**Java 21 or later.** Every published artifact is Java 21 bytecode (class-file major 65); there has never been a Java 17
build, and a Java 17 runtime cannot load the SDK. The `claude` CLI must be installed and authenticated.

```java
// One answer, one call
String answer = Query.text("What is 2+2?");

// A multi-turn session that keeps its context
try (ClaudeSyncClient client = ClaudeClient.sync()
        .workingDirectory(Path.of("."))
        .build()) {
    String summary = client.connectText("Summarize this project's README");
    String modules = client.queryText("Now list its modules");
}
```

## 1.8.0 in brief

1.8.0 fixes four Jackson vulnerabilities by moving to Jackson 2.22.3 and 3.2.3. Published 1.5.1, 1.6.0 and 1.7.0 declare
Jackson 2.22.2 and 3.2.2, which carry CVE-2026-89407, CVE-2026-89425, CVE-2026-91776 and CVE-2026-91777 (CVSS 7.5), so
upgrade to 1.8.0. It also repairs three wire defects: a required MCP configuration that cannot be written now fails before
the CLI starts, control responses carry `subtype` once, and hook responses keep their nested fields. Builder users need no
code change; direct `new CLIOptions(...)` calls and three `ParsedMessage` record constructors gain components, and the
unused `ClaudeCliPrototype` class is removed. [Release notes](https://github.com/markpollack/claude-agent-sdk-java/blob/v1.8.0/release-notes/1.8.0.md).

**1.7.0:** Closing or cancelling a session destroys the Claude CLI process tree before closing streams, unblocking readers and preventing the CLI from surviving cancellation.

**1.5.0:** A security, packaging and behaviour-correction release: it raises the Jackson floors so they reach standalone consumers, embeds the Apache licence in every archive, publishes a CycloneDX 1.6 SBOM, and stops a no-argument `connect()` from sending a prompt of its own. It follows 1.4.0, which bumped the MCP SDK from 0.15.0 to 2.0.0 (mcp-core 2.0.0), clearing CVE-2026-35568; 1.8.0 uses MCP SDK 2.0.1. See [What's New →](/docs/claude-agent-sdk/whats-new).

<Warning>
**Upgrade from 1.4.0.** If you use 1.4.0 without importing a BOM that manages Jackson,
your runtime closure resolves Jackson 2.21.2 and Jackson 3.0.3, which carry 23 known
vulnerabilities (8 HIGH). 1.5.0 declares the Jackson 2.21.6 / 3.1.6 floors directly on
the published module, so the same no-BOM consumer resolves zero findings. 1.4.0 stays
published and stays exposed — Maven Central is immutable, and nothing repairs it
retroactively.
</Warning>

## How it operates

The SDK does not call the Anthropic API. It **spawns the Claude Code CLI as a child
process** and speaks the stream-JSON control protocol to it over stdin and stdout. That
shapes what you need to know:

- The `claude` executable must be installed and authenticated on the machine that runs
  your code. The SDK discovers it on `PATH` and in the usual install locations.
- `ANTHROPIC_API_KEY` is passed through to the child process when set. Environment
  inheritance is otherwise a whitelist, not a copy of your whole environment.
- Every session consumes real model usage and is billed. That includes the integration
  test suite in the SDK repository. A no-argument `connect()` sends nothing on its own:
  from 1.5.0 it starts and initialises the session and leaves the first turn to your
  `query(...)`. Before 1.5.0 it substituted a literal `"Hello"` and billed that turn.
- The child process, and its descendants, are terminated on close.

## MCP servers

`McpServerConfig` is a sealed interface with four server types (1.8.0):

| Type | Record | Configured with | How it runs |
|---|---|---|---|
| stdio | `McpStdioServerConfig(command, args, env)` | a command line | External process, passed to the Claude CLI with `--mcp-config` |
| SSE | `McpSseServerConfig(url, headers)` | a URL and optional headers | External server, passed with `--mcp-config` |
| HTTP | `McpHttpServerConfig(url, headers)` | a URL and optional headers | External server, passed with `--mcp-config` |
| In-process | `McpSdkServerConfig(name, McpSyncServer instance)` | an MCP Java SDK server object in your JVM | Managed by the SDK over the `mcp_message` control protocol; no external process. Tool calls are not yet implemented (below) |

Register a server by name with `CLIOptions.Builder.mcpServer(name, config)`, or on a client spec with `ClaudeClient` `SyncSpec`/`AsyncSpec` `.mcpServer(name, config)` and `.mcpServers(Map)`. Its tools are named `mcp__{name}__{tool}`, for example `mcp__fs__read_file`, which is the name to use in an allowed-tools list.

<Note>
**In-process servers list tools but cannot yet run them.** In 1.8.0 the SDK answers `initialize` and the list methods for an `McpSdkServerConfig`, but a `tools/call`, `resources/read` or `prompts/get` through it returns the JSON-RPC error "not yet implemented". Use a stdio, SSE or HTTP server for tools Claude must call.
</Note>

From 1.8.0, a requested `--mcp-config` that cannot be written fails before the CLI is launched, with `TransportException("Failed to prepare required MCP configuration")` (`f555e72b`). In 1.7.0 the SDK logs a warning and launches the CLI without the MCP servers.

## Role in the Lab

- **[Agent Client](/projects/agent-client)** uses the SDK for Claude Code integration (`agent-claude`), with Spring Boot lifecycle and sandbox isolation
- **[Agent Workflow](/projects/agent-workflow)** does not depend on this SDK. Its `ClaudeStep` runs the `claude` CLI as a subprocess through Workflow's own `ClaudeSyncClient` interface, whose default implementation an application can replace
- **[Agent Experiment](/projects/agent-experiment)** 0.9.0 invokes Claude through `ClaudeSdkInvoker` (`experiment-claude`). On main it is replaced by `AgentClientInvoker`, which reaches this SDK through Agent Client
